# План подключения второй фирмы «Инновейв» (общий режим: НДС + НСП)

> Планируем ДО выгрузки. Innowave на общем режиме, поэтому это не «те же
> файлы под другой папкой»: НДС и НСП меняют смысл почти каждой цифры —
> выручки, себестоимости, дебиторки, маржи, ДДС. Ниже: что отличается, что
> должно появиться в выгрузках, что доработать в портале и в каком порядке.
> Учётная политика — `УЧЕТНАЯ_ПОЛИТИКА.md`, список файлов —
> `ТЗ_ВЫГРУЗКА_ИННОВЕЙВ.md`.

## 1. Чем Инновейв отличается от Хайджин

| | Innowave Hygiene | Innowave |
|---|---|---|
| Режим | единый налог (с оборота) | **общий**: НДС + налог на прибыль |
| НДС | нет | есть, раздельный учёт входящего/исходящего |
| НСП (налог с продаж) | входит в единый | **начисляется отдельно** |
| ЭСФ | выписывается | выписывается, и является ключом сверки с налоговой |
| Счета налогов | 8191 «Единый налог» | 1540 / 3430 / 8100 + 3410 налог на прибыль |
| Выручка в P&L | = сумма документа | **сумма без НДС** |

**Ставки — подтвердить у бухгалтера перед расчётами** (в политике они
помечены `[подтвердить]`): НДС 12%, налог на прибыль 10%, ставки НСП для
торговли — свои для наличного и безналичного расчёта. Портал не должен
«знать» ставку по умолчанию: он берёт суммы налогов из выгрузки, а ставку
использует только для проверки «сумма налога сходится со ставкой».

## 2. Что меняется в смысле цифр (главное)

1. **Выручка.** У Хайджин выручка = сумма документа. У Инновейв выручка для
   P&L = **сумма без НДС**, а НДС — обязательство, а не доход. Если считать
   одинаково, прибыль второй фирмы будет завышена примерно на 12%.
2. **Себестоимость и остатки.** Товар приходуется без входного НДС (он идёт
   к зачёту на 1540). Если НДС «сядет» в себестоимость, маржа поедет.
   Исключение — НДС, не принимаемый к зачёту (8100): он в расходы.
3. **Дебиторка.** Клиент должен **с НДС и НСП** — тут сумма документа, а не
   нетто. То есть выручка и долг считаются от разных баз: типичное место
   ошибки при объединении двух фирм в один отчёт.
4. **ДДС.** Уплата НДС/НСП — отдельные статьи оттока; поступление НДС от
   покупателей внутри оплат не выделяется. В отчёте ДДС налоги показываем
   отдельной строкой, а не растворяем в «прочих выплатах».
5. **Консолидация.** «Обе фирмы» в отчётах = Хайджин (брутто, единый налог)
   + Инновейв (нетто по выручке). Складывать выручку «как есть» нельзя;
   в сводном P&L строка выручки должна быть нетто по обеим, с отдельной
   строкой налогов с оборота у Хайджин.

## 3. Что должно быть в выгрузках дополнительно к списку ТЗ

К требованиям `ТЗ_ВЫГРУЗКА_ИННОВЕЙВ.md` для Инновейв добавляются:

**Реализация:** `СуммаНДС`, `СтавкаНДС`, `СуммаНСП`, `СтавкаНСП`,
`СуммаБезНДС` (или «Всего» и «Сумма» так, чтобы нетто и брутто различались
однозначно), **номер и дата ЭСФ**, счёт учёта НДС.

**Поступление товаров и услуг:** `СуммаНДС`, `ЗачетНДС` (да/нет), `БезНДС`,
счёт учёта НДС, номер ЭСФ поставщика. Хорошая новость: эти колонки уже есть
в пакете Хайджин — там они просто пустые, значит запрос менять почти не
придётся.

**Возвраты:** те же поля НДС/НСП, иначе корректировка налога не сойдётся.

**Отдельно (для сверки с налоговой):** книга покупок и книга продаж за
период, либо реестр ЭСФ — входящие и исходящие. Это и есть то, чем портал
будет проверять правильность: обороты по 3430 против книги продаж, по 1540
против книги покупок.

## 4. План счетов: что добавится

Рабочий план счетов у обеих фирм общий (Типовой КР), но у Инновейв
задействуются счета, которых у Хайджин нет вовсе:

| Счёт | Наименование | Зачем |
|---|---|---|
| 1540 | НДС к возмещению (входящий) | зачёт по покупкам |
| 3430 | НДС к оплате (исходящий) | обязательство перед бюджетом |
| 8100 | НДС, не принимаемый к зачёту | в расходы |
| 3410 | Налог на прибыль к оплате | общий режим |
| 3440 `[уточнить код]` | Налог с продаж к оплате | НСП |
| 7xxx/8xxx | Расходы по НСП | НСП в расходах периода |

**Действие:** попросить выгрузку `ПланыСчетов.Хозрасчетный` из базы
Инновейв — полный справочник с кодами, наименованиями, признаком
забалансовости и списком субконто. Тогда портал перестанет опираться на
зашитый список и будет строить отчёты по реальному плану каждой фирмы.
(По Хайджин полный план тоже стоит забрать: сейчас у нас только 75 счетов,
реально задействованных в проводках.)

## 5. Что дорабатывать в портале

1. **Признак режима у организации.** Сейчас `organization` — просто метка.
   Нужен атрибут «налоговый режим» (единый / общий), от него зависит расчёт
   выручки и набор налоговых строк. Без него отчёты по двум фирмам считать
   одинаково нельзя.
2. **Поля налогов в моделях продаж/закупок/возвратов**: сумма НДС, сумма
   НСП, признак зачёта, номер ЭСФ. Импортёры их заполняют, если колонки
   есть; для Хайджин остаются пустыми.
3. **Выручка нетто в аналитике и P&L** для фирм на общем режиме; в
   консолидации — единая база.
4. **Раздел «НДС»** (внутри Финансов): начислено / к зачёту / к уплате по
   периодам, сверка с оборотами 3430 и 1540 из журнала проводок и с книгами
   покупок/продаж.
5. **ДДС**: налоги отдельными статьями оттока.
6. **Проверки**: сумма НДС в документе против ставки; реализация с НДС без
   номера ЭСФ; поступление с зачётом НДС без ЭСФ поставщика; расхождение
   «книга продаж ↔ обороты 3430».

## 6. Порядок работ

1. **Подтвердить у бухгалтера** ставки (НДС, налог на прибыль, НСП нал/безнал)
   и коды счетов НСП — снять пометки `[подтвердить]` в учётной политике.
2. **Забрать полный план счетов** обеих баз (`ПланыСчетов.Хозрасчетный`).
3. **Обновить учётную политику**: раздел по Инновейв с реальными ставками,
   счетами и правилом «выручка нетто».
4. **Разовая выгрузка Инновейв** по ТЗ + налоговые колонки → своя папка
   Drive → проверка в «Журнал загрузок».
5. **Портал**: режим у организации → поля налогов → выручка нетто →
   раздел «НДС» → проверки.
6. **Сверка**: обороты 3430/1540 из журнала проводок против книг
   покупок/продаж и против деклараций.
7. Только после этого — регламентное задание на обе фирмы.

Шаги 1–3 не требуют программирования и делаются параллельно с текущей
работой по Хайджин; шаг 4 можно запускать сразу после 1.
