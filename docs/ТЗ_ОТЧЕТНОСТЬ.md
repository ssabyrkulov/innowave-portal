## ДДС — готов на ~90%

Все четыре денежных потока загружаются, остатки есть. Не хватает трёх вещей:

1. **Статья ДДС на каждом платеже.** Сейчас у платежа есть только текстовое
   «Основание»/«ВидОперации». Для отчёта по статьям (и для деления на
   операционную/инвестиционную/финансовую деятельность) нужна колонка
   `СтатьяДДС` в четырёх денежных выгрузках. БДДС-план в портале уже ведётся
   по статьям — факт должен зацепиться за те же статьи, а не угадываться по
   тексту основания.
2. **Внутренние переводы** (банк → касса, между счетами, конверсия валют).
   Если их не пометить, они выглядят как доход и расход одновременно и
   раздувают обороты. Признак: ВидОперации по обеим сторонам перевода.
3. **Полнота второй фирмы** — денежные выгрузки Innowave должны идти так же
   регулярно, как Hygiene.

## P&L — главные дыры

P&L по методу начисления. Выручка есть; дальше по убыванию важности:

1. **Себестоимость продаж (COGS).** Уже написана в
   `ТЗ_ВЫГРУЗКА_РЕАЛИЗАЦИИ.md` (колонки 16–21: Себестоимость, СчётДоходов,
   СтатьяДоходов, СчётРасходов, СтатьяРасходов, Организация). Эрмек не
   добавил. Без этого нет валовой прибыли — а значит нет P&L вообще.
2. **Услуги полученные** (аренда, реклама, логистика, связь) — акты
   поставщиков услуг. Сейчас видны только их оплаты (денежный поток), а для
   P&L нужен расход в периоде оказания услуги. Выгрузка «Поступление
   товаров и услуг» приходит только товарной частью.
3. **Зарплата** — начисления (не выплаты). Выгрузка «Начисление зарплаты»
   или итог по счёту.
4. **Сумма списаний.** ВыгрузкаСпис отдаёт только штуки. Для P&L списание —
   это расход в сомах (себестоимость списанного). Добавить колонку «Сумма».
5. **Амортизация и ОС** — если основные средства есть на балансе.
6. **Курсовые разницы** — закупки в USD, продажи в KGS; при изменении курса
   между поступлением и оплатой возникает доход/расход, который иначе
   «размажется» по себестоимости.

## Баланс — не собирается без двух вещей

Активы = деньги (есть) + дебиторка (есть) + товар в деньгах + ОС + авансы.
Пассивы = кредиторка + займы + капитал + накопленная прибыль.

1. **Входящие остатки на дату старта учёта.** Принципиально: баланс —
   накопительный отчёт, и без вводного баланса (капитал, начальные остатки
   по всем счетам) он не сойдётся никогда, сколько бы оборотов мы ни
   загрузили.
2. **Товарные остатки в деньгах.** Формат ВыгрузкаОст уже содержит
   СуммаОстаток — надо только починить выгрузку (файл пустой).
3. **Кредиторка поставщикам.** Закупки есть, оплаты поставщикам есть, но
   они не связаны. Считать «закупки − оплаты по контрагенту» можно, но
   надёжнее взять сальдо счёта 3110 из ОСВ.
4. **Займы и кредиты, подотчёт (авансовые отчёты), взаиморасчёты
   учредителей** — не выгружаются вовсе.

## Самый короткий путь: ОСВ

Вместо шести новых документных выгрузок все три отчёта закрывает **одна**:
**оборотно-сальдовая ведомость помесячно** — счёт, остаток на начало,
обороты Дт/Кт, остаток на конец.

- Баланс = сальдо счетов 1000–5000 на дату.
- P&L = обороты счетов 6000–9000 за период (выручка 6110, себестоимость
  7210, расходы по статьям).
- Проверка ДДС = обороты денежных счетов против наших банк/касса выгрузок.

Документные выгрузки при этом остаются детализацией (по кому, по чему,
почему), а ОСВ становится каркасом и сверкой. Классификатор портала уже
распознаёт файл «Оборотно-сальдовая» — не хватает только импортёра и самого
файла.

Формат: Счёт (код), НачОстатокДт, НачОстатокКт, ОборотДт, ОборотКт,
КонОстатокДт, КонОстатокКт; помесячно; по каждой фирме отдельно; включая
субсчета. Идеально — вторым листом расшифровка по субконто для 3110
(поставщики) и 1610 (товары).
