# Целевая архитектура портала (после пакета выгрузок 09.08.2026)

> Ответ на вопрос «как теперь выстроить сайт». Опирается на
> АУДИТ_ИНТЕРФЕЙСА.md (что болит сейчас), АРХИТЕКТУРА_ОТЧЕТНОСТИ.md
> (как проверять учёт) и АНАЛИЗ_20_ВЫГРУЗОК.md (что дают новые данные).

## Принцип: три слоя данных, один порядок правды

1. **Журнал проводок — ядро.** Единственный источник учётной истины:
   из него портал сам строит ОСВ, Баланс, P&L, сальдо любого счёта.
2. **Документные выгрузки — детализация.** Кто, что, сколько штук, почему:
   реализации, возвраты, кассы, банк, ГТД, зарплата, подотчёт. Связаны с
   ядром через ДокументGUID, со справочниками — через
   КонтрагентGUID/НоменклатураGUID.
3. **SalesDoc — операционный слой.** Поле: агенты, визиты, заказы, склад SD.
   Read-only зеркало, связка с 1С по GUID (code_1C).

Правило навигации: **любая цифра кликается вниз по слоям** —
отчёт → счёт → проводки → документ → (если есть) документ SD. Ни одного
«просто числа», происхождение которого нельзя раскрыть.

Правило доверия: на каждой странице — бейдж свежести («1С от 09.08 17:02,
SD от 09.08 18:40») и учёт «Проблемных документов»: помеченные на
удаление/непроведённые исключены из всех цифр и видны отдельным списком.

## Меню: 6 групп вместо 16 пунктов

### 1. Главная — «состояние компании сегодня»
Деньги на счетах (наш расчёт ↔ остатки 1С), продажи и поле сегодня,
алерты: расхождения сверок, просроченная дебиторка, проблемные документы,
сбои автосинка. Каждый алерт — ссылка в свой раздел.

### 2. Деньги
- **Платежи** (Календарь + Платежи объединены: один список, вид «календарь/таблица»)
- **ДДС**: факт по статьям из ПКО/РКО/ПП + план-факт с БДДС; внутренние
  переводы и конвертации помечены, не задваивают
- **Остатки денег**: расчёт портала ↔ счета 1110/1210/1220 из журнала ↔
  файл «Остатки ДС»

### 3. Продажи
- **Аналитика** (как есть)
- **Дебиторка**: долг = реализации − безнал − **наличка из ПКО** − возвраты;
  агент за точкой, маршрутные дни; сверка с сальдо 1410 из журнала
- **Агенты**: «Сегодня в полях», визиты, заказы
- **Мой день** (страница агента)

### 4. Товары
- **Остатки**: три источника рядом — наша математика ↔ журнал (1610 с
  количеством) ↔ SD, с расхождением и разбором
- **Движения**: поступления, списания (куда ушло — счёт/субконто, суммы из
  журнала), перемещения, оприходования, инвентаризации (учёт vs факт)
- **Партии импорта**: landed cost = инвойс → ГТД → ТЗР по ПоступлениеGUID
- **Карточка товара**: GUID-связка 1С ↔ SD, остатки по складам, движение,
  себестоимость, маржа

### 5. Финансы (новый раздел — из журнала проводок)
- **P&L помесячно**: выручка, себестоимость, валовая, расходы по статьям,
  зарплата (начисления), курсовые; обороты без документов закрытия
- **Баланс** на дату: деньги, товар, дебиторка/кредиторка, займы, капитал
- **ОСВ** за период, клик по счёту → проводки
- **Зарплата**: начислено ↔ выплачено по сотруднику
- **Подотчёт**: остатки «на руках» по авансовым отчётам

### 6. Контроль
- **Сверка долгов** (бывш. «Сверка SD»)
- **Сверка документов** (бывш. «Сверка по ID») — строгий GUID-матч
- **Проблемные документы** — что исключено и почему
- **Проверки** (checks) + Налоговая (Байго) + Журнал загрузок
- **Диагностика** — все зонды SalesDoc, отдельно от рабочего пути

## Сквозные карточки (открываются из любой таблицы)

- **Карточка контрагента**: долг и сальдо 1410, оплаты (безнал и нал),
  реализации, возвраты, закреплённый агент, визиты, комментарии 1С.
- **Карточка товара**: остатки, движения, маржа, партии, фасовки (*4/*6).

Это закрывает главный запрос аудита — «собрать картину по одной точке в
одном месте», и убирает дубли: разделы показывают срезы, карточка — всё.

## Роли и вход

Стартовая страница по роли: агент → Мой день; бухгалтер/офис → Контроль;
руководитель → Главная. Права уже есть, надо только привязать редирект.

## Пайплайн данных (то, что делает сайт честным)

Drive (25 файлов, автосинк 15 мин) → классификатор (дополнить: журнал,
справочники, платёжный ордер, допрасходы) → импортёры с фильтром
«проблемных» → пересчёт витрин (остатки, дебиторка, P&L-кэш) → бейджи
свежести. SalesDoc-зеркало — своим циклом, как сейчас.

Мультифирма: вторая фирма (Innowave общий) подключается тем же пакетом
выгрузок в свою папку — интерфейс уже умеет переключатель организаций.

## Порядок стройки

1. **Данные** (фундамент): импортёры журнала проводок, справочников,
   проблемных документов; правки классификатора; GUID-колонки в
   существующих импортёрах. Без интерфейса — только «Контроль» покажет
   новые загрузки.
2. **Финансы**: страницы ОСВ → P&L → Баланс (в этом порядке — каждая
   следующая опирается на предыдущую), сверка ДДС по счетам.
3. **Уборка по аудиту**: группировка меню, Календарь+Платежи, переименование
   сверок, карточка контрагента, наличка в дебиторке.
4. **Полировка**: карточка товара, роли, человеческие ошибки, мобильная
   версия, запоминание панелей.

Каждый этап самостоятелен: после любого из них сайт целостен и полезнее,
чем до него.
