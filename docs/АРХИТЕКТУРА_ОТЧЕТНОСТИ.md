# Самопроверяющаяся отчётность

> Задача: сформировать P&L, Баланс и ДДС и одновременно проверять их
> правильность — потому что сам учёт может быть неправильным.

## Принцип

ОСВ проверить саму собой нельзя: двойная запись сходится по построению, даже
если половина операций разнесена не туда или не проведена вовсе. Ошибки учёта
ловятся только **независимым источником** — данными, которые попали в портал
другим путём и не могли «испортиться» вместе с проводками.

У портала таких независимых путей уже четыре, и это его главное преимущество:

| Якорь | Источник | Насколько твёрдый |
|---|---|---|
| Деньги | банковские выгрузки, касса, снапшот БанкКасса | самый твёрдый: банк не врёт |
| Товар в штуках | закупки − продажи + возвраты − списания; остатки SalesDoc; журнал склада SD | твёрдый |
| Дебиторка | расчёт по документам; баланс SalesDoc (сверка уже работает) | твёрдый |
| Налоговый контур | выгрузки ред. 1.7 | независимая вторая база |

Поэтому каждый отчёт строится **двумя путями сразу**: каркас — из ОСВ
(проводки), проверка — из документов и внешних систем. Совпало — строка
зелёная. Разошлось — это не «отчёт готов с оговоркой», это найденная ошибка
учёта с суммой и адресом.

## Верификационные тождества

Каждое — проверка, которую портал считает автоматически и показывает рядом
со строкой отчёта.

### Внутри ОСВ (формальные)
1. Σ дебетовых сальдо = Σ кредитовых — на начало и на конец.
2. Нет «красных» сальдо: активный счёт с кредитовым остатком (товары < 0,
   касса < 0) — ошибка разноски.
3. Непрерывность: конечный остаток месяца N = начальный месяца N+1 по
   каждому счёту.

### ДДС ↔ реальные деньги
4. По каждому счёту/кассе: остаток на начало + приток − отток = остаток на
   конец, где притоки/оттоки — наши банковские и кассовые выгрузки, а
   остатки — снапшот БанкКасса.
5. Обороты денежных счетов ОСВ (1110/1210) = обороты загруженных выписок.
   Разошлись — в 1С есть денежные проводки без банка или наоборот.
6. Внутренние переводы: Σ переводов «из» = Σ переводов «в» (иначе деньги
   «рождаются» в пути).

### P&L ↔ документы
7. Выручка (обороты 6110) = Σ реализаций из выгрузки за период.
8. Себестоимость (обороты 7210) ≈ проданные штуки × закупочные цены
   (проверка разумности, допуск на метод оценки).
9. Валовая маржа по товару в разумном коридоре: себестоимость выше цены
   продажи — сигнал (уже есть похожая проверка цен в «Контроле»).
10. Списания в P&L = списанные штуки × себестоимость.

### Баланс ↔ независимые источники
11. Сальдо 1410 (покупатели) = расчётная дебиторка портала; третьим углом —
    баланс SalesDoc (сверка долгов уже работает, подключается как есть).
12. Сальдо 1610 (товары) = расчётные остатки в деньгах = ВыгрузкаОст;
    в штуках — против остатков SalesDoc.
13. Сальдо 3110 (поставщики) = закупки − оплаты поставщикам.
14. Деньги в балансе = остатки по выпискам (якорь №1).

### Между отчётами (связки)
15. Чистая прибыль P&L за период = прирост нераспределённой прибыли в
    балансе (с поправкой на дивиденды/изъятия).
16. Конечный остаток денег в ДДС = деньги в балансе на ту же дату.
17. Δ дебиторки + Δ запасов − Δ кредиторки объясняет разрыв между прибылью
    и денежным потоком (косвенный ДДС как проверка прямого).

### Полнота (уже работает, расширить)
18. Пропуски нумерации документов (правило «Контроля» — уже покрывает
    реализации, закупки, списания).
19. Непроведённые/удалённые (фильтр в выгрузках + колонки-признаки).
20. Сверка документов с SalesDoc по идентификаторам (раздел «Сверка по ID»).

## Как это выглядит в портале

Раздел «Отчётность»: три вкладки — P&L, Баланс, ДДС. У каждой строки статус:

- ✅ **сходится** — тождество выполняется (допуск на копейки округления);
- ⚠️ **расхождение N сом** — кликабельно: раскрывается, какое тождество
  нарушено, обе стороны равенства и ссылка на детализацию (реестр операций,
  сверку, карточку);
- ❔ **проверить нечем** — независимого источника нет (честно, а не молча).

Сводный индикатор наверху: «Баланс проверен на 78% суммы активов». Это и
есть ответ на «учёт может быть неправильным» — отчёт всегда говорит, какой
его части можно верить и почему.

## Порядок сборки

1. **ДДС — первым, уже сейчас.** Данные есть: банк, касса, снапшоты
   остатков. Тождество №4 сразу покажет, бьются ли выписки с остатками.
   ОСВ для этого не нужна.
2. **Импортёр ОСВ** (как только Эрмек отдаст файл): таблица
   `trial_balance(org, period, account, нач/об/кон Дт-Кт)` + формальные
   проверки №1–3.
3. **Баланс** из сальдо ОСВ + тождества №11–14 (дебиторка и деньги
   проверяются сразу, товары — после починки ВыгрузкаОст).
4. **P&L** из оборотов ОСВ + №7 сразу, №8–10 — после колонок себестоимости.
5. **Связки** №15–17 — когда есть все три отчёта.

Пункт 1 не зависит от Эрмека вообще. Пункты 3–4 частично работают с первого
дня: чего проверить нечем, отчёт честно помечает, и по мере поступления
выгрузок доля проверенного растёт сама.
