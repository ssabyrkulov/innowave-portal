## Чем лучше текущих выгрузок

1. **GUID везде.** Сейчас в реализациях 0/5233 GUID — «Сверка по ID» с SD
   работает на догадках. Здесь 100% + перекрёстные ссылки:
   возврат→ОтгрузкаGUID→реализация, ГТД/ТЗР→ПоступлениеGUID→поступление,
   ПП→ОснованиеGUID.
2. **Себестоимость продаж** (пункт 2 списка Эрмеку) — в каждой строке
   реализации. Валовая прибыль и маржа по товару/клиенту/агенту считаются сразу.
3. **СтатьяДДС + счета + субконто** во всех денежных документах (пункт 4) —
   факт ДДС цепляется к статьям БДДС-плана, а не угадывается по тексту.
4. **Наличные оплаты покупателей** — 1 593 ПКО на 42,75 млн. Дебиторка
   перестаёт занижаться, баннер «наличка не загружается» уходит.
5. **Внутренние переводы помечены** (взнос в банк / получение наличных /
   конвертация) — обороты ДДС не задваиваются.
6. **«Проблемные документы»** — фильтр «только проведённые, без пометки
   удаления» (пункт 7) реализован даже лучше, чем просили: отдельным файлом
   со статусом, GUID и суммой — портал может исключать и показывать причину.
7. **Новые сущности целиком**: подотчёт, зарплата, конвертация, ГТД, ТЗР,
   инвентаризация, оприходование, перемещения, остатки денег.
8. **Автор и комментарий** в каждом документе — видно, кто завёл документ.
9. Числа — числами; полный период с начала учёта; свежесть — по вчера.

## Чего всё ещё не хватает

1. **ОСВ помесячно** (пункт 1 списка Эрмеку) — в пакете нет. Баланс всё ещё
   не собрать: нет вводных остатков и сальдо счетов.
2. **Сумма в списаниях** (пункт 5) — по-прежнему только штуки. «Куда» теперь
   видно (СчётЗатрат/Субконто), «сколько в сомах» — нет.
3. **Акты услуг** — «Поступление товаров и услуг» содержит только товары
   (ВидОперации=Товары во всех строках). Аренда/связь/реклама-услуги для P&L
   так и не выгружаются.
4. **НоменклатураGUID и КонтрагентGUID** — нет ни в одном файле; сверка
   номенклатуры с SD (code_1C) остаётся по названиям.
5. **Остатки (товары и деньги) без даты снапшота** внутри файла — дата только
   по времени изменения файла.
6. **Зарплата без взносов работодателя** (соцфонд/налоги) — для полного P&L
   по ФОТ их надо добавить.
7. **Только Хайджин** — по второй фирме (Innowave общий) такого пакета нет.
8. Даты — строками; наши импортёры это умеют, но при новых импортёрах помнить.

## Как встраивать (порядок работ)

0. **Сначала классификатор.** Два имени лягут не туда при попадании в папки
   автосинка: «Платежный ордер списание ДС» словом «списание» уедет в
   товарные списания; «Дополнительные расходы» словом «расходы» — в денежные
   расходы. Добавить правила раньше существующих. «Авансовый отчет»,
   «Инвентаризация», «Оприходование», «Перемещение» сейчас честно
   unsupported; «Конвертация», «Начисление зарплаты», «ГТД», «Проблемные
   документы» — правил нет вовсе.
1. **Бесплатные победы** — существующие импортёры уже съедят: реализация
   (польются GUID и себестоимость), возвраты (ОтгрузкаGUID), поступления,
   списания, ПКО/РКО/ПП, остатки товаров.
2. **Новые импортёры по ценности**: (а) проблемные документы — фильтр для
   всего остального; (б) ГТД + допрасходы — landed cost; (в) зарплата;
   (г) авансовые отчёты; (д) конвертация; (е) инвентаризация/оприходование/
   перемещения.
3. **Сверка по ID** переключается с догадок на строгий GUID-матч по всем
   вкладкам; перемещения получают сторону 1С.
4. **Дебиторка**: добавить наличные оплаты из ПКО в расчёт долга.
5. **P&L**: валовая прибыль из реализаций + зарплата + курсовые из
   конвертации; дыры — услуги и суммы списаний (запросить у Эрмека вместе с
   ОСВ).

## Дополнение: журнал проводок и справочники (09.08.2026)

### Журнал проводок — замена ОСВ, и это лучше

`Хайджин_УПРАВЛЕНКА_Журнал проводок.xlsx`: **19 470 проводок / 5 861
документ**, 25.09.2024–08.08.2026 — вся главная книга с первого дня учёта.
Колонки: Период, Документ, ДокументGUID, СчётДт/Кт с наименованиями,
Субконто Дт/Кт 1–3, Сумма, валютные суммы, **КоличествоДт/Кт**, Содержание,
Активность.

Проверки пройдены:

- **Двойная запись сходится**: обороты Дт = Кт = 1 381 211 690 сом,
  75 счетов, Активность=Нет — 0 строк.
- **Учёт закрывается**: 1 067 проводок «Закрытие месяца» + 244 «Закрытие
  месяца по ЗП» — доходы/расходы сворачиваются на 5999 помесячно. При
  построении P&L обороты 6xxx/7xxx/8xxx надо брать **без** документов
  закрытия (иначе обороты взаимно занулены), либо читать финрезультат
  прямо из проводок 5999→5300.
- **Вводных остатков нет и не нужно**: учёт начат с нуля 25.09.2024
  (капитал и займы внесены проводками), значит Баланс строится
  накопительно с первого дня — проблема «входящих остатков» снята.
- Товарные проводки несут **количество** — движение товара в штуках и
  деньгах доступно из одного файла.

Что это открывает: ОСВ за любой период строится самим порталом (свернуть
проводки по счёту), Баланс — сальдо счетов 1000–5000 на дату, P&L — обороты
6xxx–9xxx без закрытий, сверка ДДС — обороты 1110/1210/1220 против наших
банк/касса выгрузок. Пункт 1 списка Эрмеку закрыт с запасом: журнал даёт
больше, чем помесячная ОСВ (детализация до проводки и субконто).
