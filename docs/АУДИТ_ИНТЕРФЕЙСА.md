# Аудит структуры и удобства портала

> Дата: 06.08.2026. Снимок состояния: 17 страниц, 16 пунктов меню,
> ~9 100 строк интерфейсного кода, из них 3 800 — одна страница «Сверка SD»
> с 23 сворачиваемыми панелями.

Аудит отвечает на четыре вопроса: где дубли, где неудобно человеку, что
убрать, что улучшить. Выводы ранжированы: сначала то, что мешает каждый
день, потом то, что просто захламляет.

---

## 1. Главная проблема: «Сверка SD» перестала быть страницей

23 сворачиваемые панели подряд, без группировки. Рабочие инструменты
(сверка дебиторки, привязка складов к фирмам, сопоставление точек) стоят
вперемешку с разовыми исследовательскими зондами (анатомия журнала, опрос
методов API, замер скорости). Человек, который пришёл посмотреть долг точки,
листает мимо «Глубокой проверки API» и «Складских методов SalesDoc».

Панели по назначению делятся на три группы:

**Рабочие (нужны постоянно):**
- Сверка дебиторки (основная таблица страницы)
- 🏬 Склады SalesDoc → фирмы
- 🔗 Сопоставление точек 1С ↔ SalesDoc
- 🧭 Найти документ
- 🔎 Почему точка здесь / не здесь
- 👣 Дебиторка × визиты
- 📚 Журнал движений склада
- 🕓 Изменения документов SalesDoc

**Разовые зонды, уже ответившие на свой вопрос** (исследование закончено,
вывод получен и встроен в рабочие механизмы):
- 🧪 Какие методы есть в API — ответ получен, полный список из документации
- 🧬 Анатомия журнала — доказала пропажу заказов неактивных агентов; сам
  признак теперь показывается в сверке («скрыто в SD»)
- 🧭 Модель агента — ответ: закрепление в карточке; уже используется дебиторкой
- 📦 Складские методы (movements-probe) — ответ: getMovement это перемещения
- 👣 Визиты SalesDoc: поля — ответ встроен в зеркало визитов
- 🔬 Глубокая проверка API (api-probe) — разовая, вопрос закрыт
- ⚡ Замер скорости — разовый
- 📒 Виды операций журнала — справка, полезна раз в квартал

**Диагностика второй линии** (нужна при разборе конкретной проблемы):
- Диагностика оплат / возвратов / структуры, Отчёт по складам,
  Оплаты: чем делить по фирмам, Остатки на складах SD

**Рекомендация.** Разделить страницу на две: «Сверка SD» — только рабочие
панели; «Диагностика SD» (без пункта меню, ссылка внизу «Сверки») — зонды и
вторая линия. Зонды не удалять: они уже дважды пригождались повторно, но им
не место на рабочем пути.

## 2. Дубли

### 2.1. Три сверки реализаций
- «Сверка SD» → панель «📦 Реализации: 1С ↔ SalesDoc» (ShipmentsCompare)
- «Сверка SD» → панель «🔗 Сверка операций по идентификатору» (ByGuid)
- «Сверка по ID» → вкладка «Реализации»

Это одна и та же задача в трёх исполнениях разных поколений. «Сверка по ID»
новее и полнее (метки, фильтры, все виды операций). Панели ShipmentsCompare
и ByGuid — предшественники, их стоит убрать, оставив в ByGuid только
сводку-таблицу готовности идентификаторов («где сверка возможна») — она
уникальна и полезна.

### 2.2. Списания в трёх местах
- Остатки → «📤 Списания товаров» (панель с разрезом «куда ушёл товар»)
- Операции → вкладка «Списания» (реестр)
- Сверка по ID → вкладка «Списания» (сверка с SD)

Формально роли разные (аналитика / реестр / сверка), но человек этого не
знает и находит «списания» трижды с разными цифрами на экране. Минимум —
взаимные ссылки; лучше — один раздел «Списания» с тремя вкладками. То же
самое с закупками (Остатки → «Закупки» и Сверка по ID → «Поступления»).

### 2.3. Три вида «остатков» без объяснения разницы
- Главная → «Расчётные остатки» (поступило − продано + возвраты − списано)
- Остатки → фактические остатки из 1С (выгрузка пока пустая!)
- Сверка SD → «Остатки на складах SalesDoc»

Три источника, три цифры, нигде не сказано, почему они разные и какая
главная. Страница «Остатки» при этом встречает пользователя словами «данных
нет» — хотя расчётные остатки есть на Главной. Рекомендация: страница
«Остатки» должна показывать все три источника рядом (расчёт / 1С / SD) с
колонкой расхождения — это и есть будущая инвентаризация.

### 2.4. Календарь и Платежи
Обе страницы показывают одни и те же платежи (`listPayments`): одна —
сеткой месяца, другая — таблицей с CRUD. Это один раздел с двумя видами.
Рекомендация: объединить в «Платежи» с переключателем «календарь/список» —
минус один пункт меню.

### 2.5. Дебиторка × визиты
Панель в «Сверке SD» отвечает «куда ехать за деньгами», но агент, маршрут и
дни визитов уже показываются в самой Дебиторке. Смысл панели — портфель
долга по агентам; ему место на странице «Агенты» или в Дебиторке отдельной
вкладкой, а не в разделе сверки.

## 3. Неудобства для человека

1. **Меню из 16 пунктов без групп.** «Сверка SD», «Сверка по ID»,
   «Налоговая», «Контроль» — четыре пункта про сверку/контроль, но они не
   рядом и названы в разной логике. Естественные группы: Деньги (Платежи,
   БДДС), Продажи (Аналитика, Агенты, Мой день), Товары (Остатки,
   Операции), Контроль (Сверка SD, Сверка по ID, Налоговая, Контроль).
2. **«Сверка SD» против «Сверки по ID»** — человеку непонятна разница по
   названиям. Первая — про долги точек, вторая — про документы. Точнее было
   бы «Сверка долгов» и «Сверка документов».
3. **Повторяющиеся эмодзи-иконки.** Два 📦, два 🧭, два 🔬, два 👣, два 🔗
   на одной странице — иконка перестаёт помогать искать глазами.
4. **Состояние панелей не запоминается.** Каждый заход — всё свёрнуто,
   каждое раскрытие тяжёлой панели — новый запрос к SalesDoc (и её лимиту
   частоты). Стоит запоминать открытые панели в localStorage и кэшировать
   последний результат зондов с отметкой «данные от …».
5. **Сырые ошибки наружу.** «Внутренняя ошибка: AttributeError: 'list'
   object has no attribute 'items'» — человек такое читать не должен.
   Нужен общий перехват: «Не получилось, техподробности скопированы» +
   кнопка копирования для передачи разработчику.
6. **Мобильная версия неравномерна.** Дебиторка адаптирована (14 правил
   hide-mobile), «Сверка SD» — ни одного: широкие таблицы на телефоне
   уезжают. Если сверкой пользуются только с десктопа — это осознанно
   зафиксировать; если нет — адаптировать хотя бы главную таблицу.
7. **Нет «где я и что дальше».** Пустые состояния не ведут за руку:
   «Остатков нет — загрузите ВыгрузкаОст» не говорит, что файл кладётся в
   папку Drive и подхватится сам. Пустое состояние должно называть
   конкретное действие конкретного человека (Эрмек кладёт файл X в папку Y).
8. **Терминология двух систем.** На странице встречаются и «точка», и
   «клиент», и «контрагент» для одного понятия; «реализация» и «заказ» для
   одного документа. Стоит выбрать по одному слову и пройтись по текстам.

## 4. Что убрать (безопасно)

| Что | Почему |
|---|---|
| Панель «Реализации: 1С ↔ SalesDoc» | заменена «Сверкой по ID» |
| Панель «Сверка по идентификатору» (ByGuid) | то же; оставить только сводку готовности |
| Зонды: api-probe, method-probe, movements-probe, замер скорости, анатомия журнала, модель агента, визиты-поля | вопросы закрыты; перенести в «Диагностику», не в основной путь |
| «Виды операций журнала» | превратить в подсказку внутри сверки |
| Дубли эмодзи | навести один набор иконок |

Убирать код зондов целиком не стоит: они дёшевы в хранении и уже дважды
спасали при новых загадках SalesDoc. Речь только о выносе с рабочего пути.

## 5. Что улучшить (по убыванию отдачи)

1. Разделить «Сверку SD» на рабочую страницу и «Диагностику» (п. 1).
2. Объединить Календарь+Платежи; сгруппировать меню (п. 2.4, 3.1).
3. Страница «Остатки»: три источника рядом с расхождением (п. 2.3).
4. Запоминание открытых панелей + кэш зондов с отметкой времени (п. 3.4).
5. Человеческий перехват ошибок вместо traceback (п. 3.5).
6. Переименовать «Сверка SD» → «Сверка долгов», «Сверка по ID» → «Сверка
   документов» (п. 3.2).
7. Пустые состояния с конкретным действием (п. 3.7).
8. Единая терминология: точка/клиент, реализация/заказ (п. 3.8).

## 6. Чего не хватает (не про уборку, про ценность)

- **Единый поиск** по контрагенту: сейчас чтобы собрать картину по одной
  точке, надо зайти в Дебиторку, Сверку и Операции. Карточка контрагента,
  открываемая отовсюду, закрыла бы это.
- **Сквозные ссылки**: из строки сверки — в карточку точки; из расхождения —
  в «Найти документ» с заполненными полями; из «Контроля» — в документ.
- **Стартовая страница по роли**: агенту — «Мой день», бухгалтеру —
  Дебиторка/Контроль; сейчас все попадают на Главную.
